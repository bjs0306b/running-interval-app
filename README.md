# 4-5주차 오픈 미션: 런닝 인터벌 앱

## 개요

이번 미션에서는 React와 Zustand를 활용하여 '러닝 인터벌 앱'을 개발합니다. 이 앱은 사용자가 설정한 달리기 및 휴식 시간을 반복하는 타이머 기능을 제공하며, 완료된 러닝 세션의 기록을 로컬 스토리지에 저장하여 조회할 수 있는 기능도 포함합니다. 또한, 사용자 경험을 향상시키기 위해 알림음 및 진동 기능을 구현하고, 코드 구조 개선과 테스트 코드 작성에도 중점을 둡니다.

모바일 웹 어플리케이션 입니다. 

chrome에서 실행하는 것을 권장합니다. (진동 기능 지원)

npm run dev를 통해 실행 가능합니다.

npm run test를 통해 테스트 코드를 실행할 수 있습니다.

https://running-interval-app.vercel.app/ 배포 링크입니다.

https://velog.io/write?id=bb91a42b-4541-4ed7-af1b-043745209895 개발 과정을 담은 블로그 글입니다.


## 기능 목록

### 0. 메인 레이아웃 및 공통 기능

- [x] React Router를 사용하여 페이지 라우팅을 구현한다.
- [x] 공통 헤더 및 푸터를 구현한다.
  - [x] 헤더에 '러닝 인터벌 앱' 타이틀을 표시한다.g
  - [x] 푸터에 '러닝' 페이지와 '기록' 페이지로 이동할 수 있는 네비게이션(탭)을 구현한다.

### 1. 러닝 페이지 (메인 타이머)

- [x] 기본 UI
  - [x] 메인 타이머 화면을 표시한다.
  - [x] '시작' (또는 '일시정지'), '설정', '리셋', '음소거' 버튼을 표시한다.
- [x] 설정 기능 (모달)
  - [x] '설정' 버튼 클릭 시, 설정 모달 창을 연다.
  - [x] '달리기' 시간을 분(min) / 초(sec) 단위로 설정할 수 있다. (기본값: 2분 0초)
  - [x] '휴식' 시간을 분(min) / 초(sec) 단위로 설정할 수 있다. (기본값: 1분 0초)
  - [x] '반복 횟수'를 설정할 수 있다. (기본값: 3회)
- [x] 타이머 핵심 로직
  - [x] '시작' 버튼을 누르면 '중지'(혹은 '일시정지') 버튼으로 텍스트가 변경된다.
  - [x] 설정된 '달리기' 시간부터 타이머가 1초씩 감소한다.
  - [x] '달리기' 시간이 0초가 되면, '휴식' 시간으로 상태가 자동 전환된다.
  - [x] '휴식' 시간이 0초가 되면, '달리기' 시간으로 상태가 자동 전환된다.
  - [x] 설정된 '반복 횟수'를 모두 완료하면 타이머가 최종 종료된다.
- [x] 알림 기능
  - [x] '달리기' ↔ '휴식' 상태가 전환될 때마다 알림음(e.g., "삑")을 재생한다.
  - [x] '음소거' 버튼을 누르면 알림음이 꺼지고, 대신 '진동'(Vibration API)으로 알림을 대체한다.

### 2. 기록 페이지

- [x] 기록 조회
  - [x] 완료된 러닝 세션의 기록(e.g., 날짜, 설정값)을 목록 형태로 조회할 수 있다.
- [x] 데이터 영속화
  - [x] 완료된 러닝 기록을 브라우저의 '로컬 스토리지(Local Storage)'에 저장하여, 새로고침해도 기록이 유지되도록 한다.

### 3. 리팩토링 (코드 구조 개선)

- [x] 컴포넌트 분리: `RunningPage`에 집중된 UI 로직을 재사용 가능한 개별 컴포넌트로 분리하여 관심사 분리 원칙을 적용하고 유지보수성을 향상시킨다.
  - [x] `StartButton`, `SettingButton`, `ResetButton`, `SilentButton` 등 제어 버튼들을 각각의 컴포넌트로 추출한다.
  - [x] 타이머 디스플레이 부분을 `TimerDisplay` 컴포넌트로 분리한다.

### 4. 테스트 코드 작성

- [x] 주요 컴포넌트 및 기능에 대한 단위/통합 테스트를 작성하여 코드의 안정성을 확보한다. Jest와 React Testing Library를 사용하여 사용자의 상호작용을 시뮬레이션하고 UI의 반응을 검증한다.

  - [x] **`RunningPage` (러닝 페이지)**
    - [x] 앱의 초기 상태(타이머 시간, 반복 횟수)가 올바르게 렌더링되는지 테스트한다.
    - [x] `Start`, `Reset`, `Setting` 버튼 클릭 시 연결된 스토어의 액션 함수들이 정상적으로 호출되는지 검증한다.
    - [x] (추가 기능) `Start` 버튼을 처음 클릭했을 때, 카운트다운 기능이 올바르게 동작하는지 테스트한다.

  - [x] **`SettingModal` (설정 모달)**
    - [x] 모달의 열림/닫힘 상태에 따라 UI가 정상적으로 렌더링 또는 미렌더링되는지 테스트한다.
    - [x] 모달이 열렸을 때, 현재 설정값(시간, 반복 횟수)이 입력 필드에 정확히 표시되는지 검증한다.
    - [x] 시간 및 반복 횟수 변경 시, 연결된 스토어의 상태 변경 함수가 올바른 값으로 호출되는지 테스트한다.
    - [x] (추가 기능) **프리셋 기능**에 대한 전체 CRUD 동작을 테스트한다.
      - [x] 저장된 프리셋 목록이 올바르게 표시되는지 확인한다.
      - [x] 새로운 프리셋을 저장하는 기능을 검증한다.
      - [x] 기존 프리셋을 클릭하여 설정을 적용하는 기능을 검증한다.
      - [x] 프리셋을 삭제하는 기능을 검증한다.

  - [x] **`RecordPage` (기록 페이지)**
    - [x] 저장된 기록이 없을 때 "아직 기록이 없습니다." 메시지가 표시되는지 테스트한다.
    - [x] 저장된 기록이 있을 때, 모든 기록의 상세 내용(날짜, 설정값)이 정확하게 렌더링되는지 검증한다.
    - [x] (추가 기능) **기록 삭제 기능**을 테스트한다.
      - [x] 삭제 버튼 클릭 시, `deleteRecord` 함수가 해당 기록의 ID와 함께 올바르게 호출되는지 확인한다.
